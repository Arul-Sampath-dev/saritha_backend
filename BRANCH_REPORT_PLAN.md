# Branch report (Excel / PDF) — plan, templates and checklist

Status: **built 2026-11-20** (backend + frontend; manual checks in BRANCH_REPORT_CHECKLIST.md §9 still open).
Changes from this plan: the PDF's Word document is built in Java (no `BranchReport.docx` template); payments are
read from the invoice payment entries (+ payment receipts for the number); the endpoint lives in
`report/export/BranchReportController`.

## 1. What we are building

A downloadable report of **one branch** for a chosen period, as **Excel (.xlsx)** or **PDF**, with everything about the
branch in that period: orders, sales, GST, payments, deliveries, expenses, petty cash, production, staff work and
customers.

| | |
|---|---|
| Periods | Chosen by the user: a day, a week, a month, 3 months, 6 months, 1 year or custom from–to — any range up to 366 days |
| Formats | Excel = full detail, one sheet per section, every row · PDF = a printable report: summary pages + the main lists |
| Who | Platform owner: any branch. Shop owner: own branch (to confirm, section 9) |
| Where | "Download report" button on the owner's branch page (and on the shop owner dashboard, if confirmed) |

**Why both formats from one data set:** the backend collects the report data once (`BranchReportData`) and two
writers turn it into a file. The Excel and the PDF always show the same numbers.

## 3. Report contents (both formats)

Money is in ₹ with Indian grouping (1,23,456.00). Dates are IST (19 Nov 2026), and times are 12-hour (4:05 pm).
"Period" means the chosen from–to, inclusive.

### 3.1 Header (cover)
- Report title: "Branch report", branch name, address, phone, GSTIN, shop owner
- Period ("1 Nov 2026 – 30 Nov 2026" / "19 Nov 2026"), generated on (date and time), generated by (user)

### 3.2 Summary
| Figure | Meaning |
|---|---|
| Orders | Invoices dated in the period (count) |
| Sales (invoiced) | Sum of invoice totals incl. GST |
| Taxable value · GST · Discount | From the same invoices |
| Collected | Payments received in the period (incl. advances), split by method (Cash, UPI, Card …) |
| Expenses | Shop + employee, split by category |
| Net cash flow | Collected − expenses |
| Delivered | Receipts generated in the period (orders handed over) |
| Outstanding (now) | Open invoices and their balance due, as of today |
| Petty cash | Added in the period · current balance |
| Deleted invoices | Count in the period |
| Change vs previous period | ▲ / ▼ % for sales, collected, expenses, net (same length just before) |

### 3.3 GST summary
Taxable value, CGST, SGST, IGST and total, for invoices dated in the period, plus a split by rate (for example 5 %).
Shown as "intra-state (CGST + SGST)" and "inter-state (IGST)".
*Note: this is a business summary. The GST filing reports (GSTR-1 format) are a separate item waiting for the CA's input.*

### 3.4 Day by day
Date · orders · invoiced · collected · expenses · net. For periods over 62 days this becomes week by week in the PDF.
Excel always keeps one row per day.

### 3.5 Orders (invoices dated in the period)
Invoice no · date · customer · phone · items (done / total) · taxable · GST · total · paid · balance · payment status ·
stage · due date · delivered on. Totals row at the bottom.

### 3.6 Payments received
Date and time · payment receipt no · invoice no · customer · method · transaction id · amount · received by.
Totals per method. *(Needs the new query, section 2.)*

### 3.7 Deliveries (final receipts)
Receipt no · date · invoice no · customer · total · method.

### 3.8 Expenses
Date · category · for (shop / employee name) · method · notes · amount. Category totals. Deleted expenses are listed
separately (date, amount, deleted by, reason).

### 3.9 Petty cash
Top-ups: date · added by · amount. Balance at the end.

### 3.10 Production
- Now: items per stage (Item accepted … Item completed), late items
- Period: orders delivered, average days order → delivery, on-time %, average time per stage (slowest marked)

### 3.11 Staff
Per person: name · role · work in the period (for example: tailor — assigned, stitched, completed; assistant —
hemming, ironing, completed; master — cut, assigned) · last activity.

### 3.12 Customers
Active · new · returning · repeat rate · average spend · top 10 customers by amount.

### 3.13 Deleted invoices
Invoice no · date · customer · amount · deleted on · deleted by · reason.

### 3.14 (Optional) Sales by item
Item name · pieces · amount (for example Blouse 14 · ₹28,000). *(Needs the new aggregation.)*

## 4. Excel template (.xlsx)

File name: `SarithaFashions_<Branch>_<from>_<to>.xlsx` (for one day: `…_<date>.xlsx`).

| Sheet | Content (section) |
|---|---|
| Summary | 3.1 header block + 3.2 figures + 3.3 GST + payment-method and expense-category splits |
| Daily | 3.4 |
| Orders | 3.5 |
| Payments | 3.6 |
| Deliveries | 3.7 |
| Expenses | 3.8 (deleted ones in a second table below) |
| Petty cash | 3.9 |
| Production | 3.10 |
| Staff | 3.11 |
| Customers | 3.12 |
| Deleted invoices | 3.13 |
| Items | 3.14 (if confirmed) |

Formatting rules (all sheets):
- Row 1: sheet title + branch + period (bold, merged); row 3: column headers (bold, light grey fill, frozen, auto-filter)
- Money cells are numbers, not text, with the format `₹#,##,##0.00` so they can be summed. Dates are real dates with the
  format `dd-mmm-yyyy`.
- Totals row at the end of each list with `SUM` formulas (live if the user edits)
- Column widths set to fit; long text (notes, address) wrapped
- Empty section → one row "No … in this period"
- Big periods: use POI's streaming writer (SXSSF) so memory stays low

## 5. PDF template (Word → PDF, same pipeline as the invoice)

File name: `SarithaFashions_<Branch>_<from>_<to>.pdf`. Template: `src/main/resources/BranchReport.docx` (A4,
portrait; wide lists in landscape sections), filled by `WordTemplate`:
`{{name}}` for single values, and a table row with `{{prefix.field}}` repeated per item.

| Page | Content | Placeholders (examples) |
|---|---|---|
| 1 Cover + summary | Logo, title, branch block, period, generated on/by; summary figures with ▲/▼ | `{{branchName}}` `{{branchAddress}}` `{{gstin}}` `{{ownerName}}` `{{periodText}}` `{{generatedAt}}` `{{generatedBy}}` `{{orders}}` `{{sales}}` `{{taxable}}` `{{gst}}` `{{discount}}` `{{collected}}` `{{expenses}}` `{{net}}` `{{delivered}}` `{{outstanding}}` `{{openInvoices}}` `{{pettyAdded}}` `{{pettyBalance}}` `{{deletedCount}}` `{{salesChange}}` … |
| 2 Money detail | GST summary; collections by method; expenses by category | `{{cgst}}` `{{sgst}}` `{{igst}}` · rows `{{methods.name}}` `{{methods.count}}` `{{methods.amount}}` · rows `{{categories.name}}` `{{categories.amount}}` |
| 3 Day by day | Daily (or weekly) table | rows `{{days.date}}` `{{days.orders}}` `{{days.invoiced}}` `{{days.collected}}` `{{days.expenses}}` `{{days.net}}` |
| 4+ Orders | Orders list + totals | rows `{{orders.no}}` `{{orders.date}}` `{{orders.customer}}` `{{orders.total}}` `{{orders.paid}}` `{{orders.balance}}` `{{orders.status}}` |
| next | Payments, deliveries, expenses, petty cash | rows `{{payments.*}}`, `{{deliveries.*}}`, `{{expenses.*}}`, `{{topups.*}}` |
| last | Production, staff, top customers, deleted invoices; footer "Generated by Saritha's Stitch Hub" + page numbers | rows `{{stages.*}}`, `{{staff.*}}`, `{{customers.*}}`, `{{deleted.*}}` |

Rules: header row repeats on every page (Word "repeat header row"); empty lists show "None in this period"
(`dropRowsWith` for empty tables); amounts right-aligned. Branch details come from the shop (same as the invoice
footer).

## 6. Backend design

### 6.1 Endpoint
`GET /v1/api/reports/branch-report?shopId=&from=&to=&format=xlsx|pdf`
- Returns the file (`Content-Type` xlsx / pdf, `Content-Disposition: attachment; filename=…`)
- `from` / `to` required (one day: from = to); `to` ≥ `from`; range ≤ 366 days; `format` default `xlsx`
- Access: platform OWNER (any shop, `shopId` required) · SHOP_OWNER (own shop, `shopId` ignored) — if confirmed
- Errors: 400 (bad dates / range / shop), 403, 502 if the PDF converter fails (Excel still works)

### 6.2 Code (module `report`, package `report.export`)
- `BranchReportData` (record): header, summary, previous-period summary, GST split, days, orders, payments,
  deliveries, expenses, deleted expenses, top-ups, production, staff, customers, deleted invoices, (items)
- `BranchReportService`: builds `BranchReportData` by **reusing** the existing read services / repositories (no
  duplicated maths), plus the new queries:
  - payment receipts by shop + `paidAt` range (repository method on the payment-receipt collection)
  - (optional) items sold: aggregation on `invoices.items` by `itemName` for invoices dated in the period
- `BranchReportExcelWriter`: POI (SXSSF) → `byte[]`, one method per sheet, shared styles (header, money, date, total)
- `BranchReportPdfWriter`: fills `BranchReport.docx` with `WordTemplate`, then calls `DocxToPdfConverter`
- Activity log: record `REPORT_DOWNLOADED` (who, branch, period, format) — optional

### 6.3 Limits / performance
- One request reads each source once; lists are loaded without paging (internal), so cap at 366 days
- PDF: very long lists make large documents and slow conversion. Proposal: the PDF lists up to 500 orders / payments /
  expenses and then says "+ N more — see the Excel report". Excel has no cap.
- Converter timeout already handled by `DocxToPdfConverter`

### 6.4 Tests
- Unit: summary / GST split / totals from sample data; Excel writer (open the bytes with POI and check sheet names,
  header row, totals); PDF placeholders all filled (no `{{` left in the .docx before conversion)
- Controller: 400 on bad range, 403 for other shop, correct filename and content type

## 7. Frontend design

- Owner branch page header: **Download report** button → modal:
  - Period: Today · Yesterday · This week · This month · Last month · Pick a day · Custom (from–to)
  - Format: Excel (full detail) / PDF (printable)
  - Note under the buttons: what is inside, and that PDFs of long periods may be summarised
  - **Download** → blob download with the server's file name, with a spinner and an error toast
- (If confirmed) the same button on the shop owner dashboard for their own branch
- API helper `downloadBranchReport({shopId, from, to, format})` in `api/reports.js` (reuse `downloadPdf` / a generic
  `downloadFile`)
